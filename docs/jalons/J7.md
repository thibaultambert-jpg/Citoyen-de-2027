# J7 — LLM local : pont natif, modèle, sortie contrainte, vérification des citations

## Réalisé

**Chaîne de réponse (`:rag`, Kotlin pur, testée sur la JVM)**
- Ne s’exécute qu’après la porte de refus, le routage et la porte d’abstention du J6 : sans extrait
  pertinent, aucun appel au modèle.
- Budget de contexte : 3 à 5 extraits dans l’ordre du classement, prompt complet ≤ 1 500 jetons (compté
  avec le tokenizer et le template du modèle) ; le dernier extrait qui ne tient pas est coupé à une
  frontière de mot et marqué « […] », jamais reformulé.
- Prompt : extraits encadrés par des délimiteurs (neutralisés s’ils apparaissent dans un texte), présentés
  comme des données à citer, jamais comme des instructions ; prompt système `llm/prompts/answer_fr.txt`.
- Sortie contrainte par grammaire GBNF : `{"answerable": …, "claims": [{"text", "sources"}]}`, au plus
  5 affirmations, chaque source parmi S1…Sn. Grammaire validée avec l’outil `test-gbnf-validator` de
  llama.cpp b11400. JSON strict, 1 nouvel essai, puis abstention.
- Vérification après génération : chaque affirmation cite au moins une source existante ; ses nombres,
  noms de mois, noms propres et citations entre guillemets doivent figurer dans les extraits cités (ou leur
  titre), après normalisation ; sinon elle est supprimée. Tout supprimé ou `answerable=false` →
  abstention. Le texte affiché est reconstruit à partir des affirmations retenues.

**Pont natif (`:llm`)**
- llama.cpp **b11400** (commit `0bb496d`, 05/10/2026, MIT), sous-module git, compilé depuis les sources
  (NDK 29.0.13113456, CMake 3.31.6 : versions de l’exemple Android de cette release). Architecture
  `mistral3` présente dans cette version.
- Une bibliothèque CPU par jeu d’instructions (armv8.0 à armv9.2 : dotprod, i8mm, SVE…), la meilleure
  chargée à l’exécution par ggml ; pages de 16 Ko ; arm64-v8a seulement.
- JNI : template de chat **lu dans le fichier GGUF** (API de llama.cpp, non recodé), comptage de jetons,
  génération gloutonne (température 0) sous grammaire, réutilisation du cache KV du préfixe commun
  (prompt système), arrêt immédiat (y compris pendant le préremplissage), embeddings. Aucun texte journalisé.

**Processus et appareil**
- Inférence dans un `Service` du processus séparé `:llm` ; modèle en mmap ; threads = cœurs hors cluster
  le plus lent ; déchargement après 2 min d’inactivité et sur pression mémoire ; arrêt si statut thermique
  ≥ SEVERE ; `max_tokens` 350 ; `n_ctx` 2 048.
- Prérequis : ≥ 6 Go de RAM et ≥ 4 Go libres, sinon « Mode sans IA » expliqué.
- Téléchargement du modèle : WorkManager, Wi-Fi uniquement, reprise (Range), vérification SHA-256 puis
  activation atomique ; import manuel du fichier (SAF), vérifié de la même façon ; suppression.

**Écran « Question »**
- Carte de l’assistant : « Activer l’assistant IA (≈ X Go, Wi-Fi) », progression, attente du Wi-Fi,
  vérification, échec, activé/désactivé, suppression.
- Extraits affichés tout de suite, puis rédaction : indicateur, « Arrêter », « Voir uniquement les
  extraits ». Réponse : mention « Contenu généré par IA », bandeau fixe de §8.9, affirmations avec
  citations tapables (extrait exact vu par le modèle), étiquettes S1… sur les cartes d’extraits.
- Programmes en parallèle : extraits seuls, sans réponse rédigée (même traitement pour chaque candidat).
- Banc d’essai (versions de débogage) : temps au premier jeton, jetons/s, pic de RAM du processus `:llm`,
  threads, variante CPU ; comparaison avec un autre fichier GGUF importé (Q4_0…).

## Tests

- `:rag` : budget de contexte, délimiteurs, réponse vérifiée, suppression (nombre, nom, mois, citation,
  source inconnue), abstentions, nouvel essai JSON, arrêt et échec.
- `:llm` (JVM) : prérequis de l’appareil, cœurs performants, stockage et activation du modèle (empreinte
  correcte, refusée, autre configuration), états de l’assistant.
- **Pont natif réel** (job CI « Native bridge ») : bibliothèque compilée pour Linux depuis les mêmes
  sources, petit modèle de test de llama.cpp (`stories15M`, empreinte vérifiée) : fichier absent, comptage,
  grammaire respectée à l’octet près, JSON décodable, sortie identique avec réutilisation du cache,
  arrêt, contexte dépassé, grammaire invalide.
- ViewModel : extraits puis réponse vérifiée, arrêt, « Voir uniquement les extraits », pas de génération
  sans modèle activé ni pour les programmes en parallèle.
