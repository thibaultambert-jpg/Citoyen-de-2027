# J2 — Pipeline mandats et votes, pack `core` signé, sync dans l’app

## Décisions de l’humain (avant J2)

GitHub Releases pour l’hébergement · pipeline en Python 3.12 · `candidates.yaml` et `identities.yaml`
fournis et validés par l’humain · clé privée Ed25519 générée par l’humain et stockée en secret CI.

## Réalisé

**Sources vérifiées, pas supposées.** L’environnement de l’agent ne joint pas les sites officiels : une
sonde (`pipeline/tools/probe_sources.py`, workflow « Pipeline source probe ») a relevé en CI les URL, formats
et champs réels avant l’écriture des adaptateurs, ainsi que les liens officiels affichés (page de scrutin AN,
URI ELI du PE : HTTP 200).

**Pipeline (`/pipeline`)** : `fetch` (cache + sha256 + date) → adaptateurs → contrôle d’identité → couverture
→ SQLite reproductible → manifeste → signature Ed25519 → rapport.
- Assemblée nationale : acteurs et mandats (AMO30, historique), scrutins publics des 16e et 17e législatures,
  positions telles que publiées (`pour`, `contre`, `abstentions`, `nonVotants`).
- Sénat : mandats sénatoriaux (`ODSEN_ELUSEN`), état civil (`ODSEN_GENERAL`).
- Parlement européen : mandats (`EU_INSTITUTION`), votes par appel nominal (`favor`, `against`,
  `abstention`), quota d’API respecté.
- RNE : mandats locaux en cours (municipaux, communautaires, départementaux, régionaux, etc.).
- Identités : un identifiant saisi à la main n’est accepté que si la source officielle a le même nom de
  famille **et** la même date de naissance, sinon la construction échoue. Le RNE (sans identifiant) exige nom,
  prénom et date de naissance.
- Couverture calculée, jamais présumée : votes « non applicable » sans lien parlementaire, « partiel » si une
  seule des assemblées liées a des votes, « indisponible » sinon.
- `pack` refuse de publier une liste vide ; workflow « Publish data packs » manuel, signé, publié dans la
  release stable `packs-current` (plus une release versionnée).

**App**
- Room v2 : tables `mandates` et `votes` (source intégrée) ; le cache étant reconstruit depuis des packs
  vérifiés, un changement de schéma vide la base (préférences en DataStore, non concernées).
- `:core:network` : téléchargement HTTPS uniquement, reprise HTTP Range, contrôle de taille.
- Vérification : signature Ed25519 du manifeste (Tink), sha256 et taille du pack, version du schéma.
- Activation atomique (une transaction Room), pack précédent conservé et restaurable (`rollback`).
- Sync quotidienne WorkManager, Wi-Fi et batterie suffisante, jamais bloquante ; pack refusé = données en
  place conservées.
- Pack embarqué dans l’APK (`assets/packs/`) installé au premier lancement avec les mêmes contrôles.
- Sans clé publique configurée, la sync est désactivée : rien de non signé n’est jamais installé.

## Tests

- Pipeline (26, hors réseau) : entrées, identités (homonyme, date différente, identifiant absent),
  couverture, construction reproductible, signature et falsification, chaque adaptateur sur des fichiers
  fictifs au format réel, assemblage de bout en bout.
- **Contrat Python ↔ Kotlin** : un pack fictif construit et signé par le pipeline avec une clé de TEST
  (graine publique) est versionné dans les tests de l’app ; Kotlin vérifie la signature Python, produit la
  même signature, lit le pack (Robolectric) ; le pipeline vérifie que le pack versionné est à jour.
- App : téléchargement (HTTPS seul, reprise, serveur sans Range, taille), vérificateur (clé étrangère,
  manifeste ou fichier modifié), installation, refus sans altération, retour arrière, synchronisation
  (installé puis à jour sans nouveau téléchargement, désactivée sans clé, signature forgée, erreur 503).

## Hypothèses

- La release `packs-current` sert d’adresse stable ; les releases de l’APK (si GitHub) n’interfèrent pas.
- Libellés de mandat construits à partir des champs officiels (« Mandat de député — 17e législature —
  Département, circonscription n° X ») ; les positions de vote restent dans le vocabulaire publié, la
  traduction en libellés français se fera à l’affichage (J3).

## Risques

- Formats officiels susceptibles d’évoluer : la sonde permet de les revérifier ; un champ manquant fait
  échouer la construction plutôt que d’inventer.
- Volume PE : un an de séances ≈ 60 requêtes ; quota de 500 requêtes / 5 min respecté par un délai de 0,7 s.
- Schéma Room toujours non versionné dans le dépôt (pas de SDK Android dans l’environnement de l’agent).
